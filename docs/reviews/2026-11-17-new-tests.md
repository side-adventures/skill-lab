## Scoring reviewer

No shortcut beats honest play in any of the five; Change Detection has the only real issues. Numbers come from the
simulations in `src/tests/<id>/scoring.review.test.ts` (the only files added). `npm test` exit 0 (49 files,
220 tests), `npm run lint` exit 0. Change Detection model: a player holds K shapes (±0.7 trial to trial), guesses
"changed" at rate g when unsure, slips on 4 % of trials, 200–1000 seeded runs.

**Change Detection (luckiest of the five)**
1. *Medium – two early mistakes cost a K=4 player 0.78 shapes* (4.41 → 3.63), about a third of the gap between K=3 and K=5. The existing unit test passes only because its player model never varies. Fix: fit K on `answers.slice(4)` (first 4 trials as warm-up). With that, two early mistakes cost almost nothing (4.42 vs 4.37) and the spread stays the same (sd 1.19 → 1.20).
2. *Medium – guessing "changed" more often when unsure raises your best score.* At K=4, g=0.45 gives a slightly higher average (4.61 vs 4.30 at g=0.05) and a much wider spread (sd 1.66 vs 0.93). Only the best run is kept, so the mean best of 10 runs is 7.59 vs 5.97. No cheap fix inside the model (a fixed g is untested); more trials is the general lever.
3. *Low/medium – large run-to-run spread for the same player.* sd 0.38 / 0.50 / 0.58 of the K3–K5 gap (2.29 shapes) for K=3 / 4 / 5; the 10th–90th percentile range for K=5 is 4.1–7.3; 11.5 % of K=3 runs beat the median K=4 run (about as noisy as N-Back, ~0.47). Source: only 20 change trials; a pooled Pashler K and the staircase mean were no better (0.48–0.70). 60 trials would bring it to about 0.37–0.53 (~+40 s).
4. *Info – scores run a bit high:* true K 3 / 4 / 5 / 8 → mean 3.33 / 4.57 / 5.56 / 8.58. Ranking unaffected.

Passed: always "same" 0, always "changed" 0, alternating 0.24, random 0.19, "changed" only on small boards 0.35;
counting the 20/20 plan from the feedback flash gains only +0.19; the MIN_GAP scale-down hits 0 % of honest runs for
K ≥ 3 and 2.3 % for K=2; a perfect player gets exactly 12.

**Backward Span**
1. *Low – easy repeating runs.* 6.8 % of 6-digit and 9.0 % of 7-digit sequences contain an A B A B run (like 3 7 3 7), easy to chunk; A B A appears in 50–58 %. Digit shares are fine (10.6–12.3 %). Fix: also reject a digit equal to the one two places back.
2. *Info (2 lives for the whole run is a spec decision):* one miss on the first 2-digit sequence costs a span-5 player 0.68 digits on average (5.26 → 4.58).

Passed: sd 0.34–0.36 of the span 4–6 gap; failing 2 digits twice saves 0 (honest result); an empty submit is impossible.

**Odd One Out — fine.** Same player: sd 0.09 (strong) / 0.16 (weak) of the 10.6 s gap; random clicking takes 232 s vs
26 s for a weak searcher; the T is never in the middle row or column, quadrants always 4/4/4/3 (300 runs).

**Advent Calendar — fine (most stable).** Same player: sd 0.05 / 0.08 of the 31.5 s gap; the path band lowers the
spread from 0.062 to 0.049; random paths 5 % 53.9, median 62.0, 95 % 70.2, 45 % of layouts inside the band; blind
clicking takes 285 s vs 85 s for a weak player.

**Symbol Code — fine.** Same player: sd 0.13–0.15 of the 32-point gap; random keys −318, one key −400, cycling −400;
the 20 s chips always add up to the score; a run with no answers is marked `failed`.

Also fine: `higherIsBetter` / `formatScore`; scoring lines in registry and SPEC match the code; timing-critical input
uses `onPointerDown` and `performance.now()`, the countdown an absolute end time, input after the end is ignored,
timers and rAF are cleared on unmount; zero / NaN / rounding edge cases handled.

Score-changing if applied (no bump needed in development): Change Detection fit on trials 5–40 or a different trial
count; Backward Span A B A filter. Luckiest to most stable: Change Detection, Backward Span, Odd One Out, Symbol Code,
Advent Calendar.

## Test auditor

Code, spec and web research only; no browser.

**Advent Calendar: R4 / M4 / Score 3 / Overall 4.** A faithful Schulte table (round 1) plus Gorbov two-set table
(round 2), and fun. The tagline hides the more interesting second round, and the switching-cost number mixes several
effects.
- Tagline describes round 1 only. Suggestion: "Open the 24 doors in order, then again, switching between stars and trees."
- Switching cost = (R2 − R1) / 24 also contains the slower downward count for trees and the order effect (R2 always second, practice shrinks it). The TMT literature uses both B − A and B / A. Keep the per-door value and add "Round 2 / round 1: ×1.9" (doesn't change the score).
- Name (user decision) stays. The icon reads at 18 px but shows the theme, not the task: acceptable.
- Rules match the code; the 5 lines fit the stage. Category Focus is right.
- Research: TMT norms (Tombaugh 2004): A ≈ 37 s, B ≈ 88 s, B − A ≈ 50 s, mean age 58 (https://pmc.ncbi.nlm.nih.gov/articles/PMC2693196). Schulte 5×5 adult times of about 25–40 s come only from commercial sites (unverified). No peer-reviewed Gorbov norms found. Bands should come from play data.

**Change Detection: R5 / M4 / Score 3 / Overall 4.** The closest to a lab task of the five. A whole-display probe with
Pashler-style K is the correct pairing (Rouder et al. 2011, https://link.springer.com/article/10.3758/s13423-011-0055-3).
The weak point is 40 trials.
1. Reliability: research uses hundreds of trials (Xu et al.: 540 trials, test–retest r ≈ .76, https://rd.springer.com/content/pdf/10.3758/s13428-017-0886-6.pdf). Ask the scoring-reviewer to simulate the run-to-run spread over 40 trials.
2. Result stats: "Shapes at the end" is a single noisy staircase point and "Most shapes" rewards a lucky streak. Better: "Average shapes, last 20 trials". Hit rate and correct-rejection rate are already the right research stats.
3. Rules: "Did one of them turn into a different shape?" is incomplete, a change always brings a new color too. Suggestion: "turn into a different shape (and color)".
- The 0.5 s sample (vs Luck & Vogel's 100 ms) is fine; changing only to a kind not on the board is standard.
- Typical K ≈ 3–4 (Luck & Vogel 1997; Cowan 2001), probably ≈ 2.5–3.5 here (approximate). Tentative bands: typical 2.5–3.5, very good 4+.
- The icon uses the same layout as Odd One Out's; make one distinct, e.g. before → after here.

**Odd One Out: R4 / M4 / Score 3 / Overall 4.** A classic T-among-Ls search with good balancing. The total time
includes mouse travel, and the slope stat is noisy.
1. "Each extra shape" comes from the medians at 16 and 36 only (5 rounds each); a least-squares fit over all 15 rounds would be steadier; label it "≈ +N ms". Doesn't change the score.
2. Icon clashes with Change Detection (see above); on its own it reads well.
3. Name is fine; "Find the T" would be plainer (optional).
- Rules match the code; category Focus is right.
- Research: target-present T-among-L slopes ≈ 20–40 ms per item (Wolfe 1998, https://www.cns.nyu.edu/~david/courses/perceptionLab/Readings/Wolfe1998.pdf). Expect steeper slopes here (large board, eye movements, a click per round). Total-time bands need play data; guess 15–30 s, unverified.

**Backward Span: R5 / M4 / Score 3 / Overall 4.** Close to WAIS Digit Span Backward (≈ 1 digit per second, digits
1–9 without repeats or runs). Name, tagline, skill line, category and icon are all good.
- Rules match the code; they don't say the pace. Suggestion: "Digits appear one at a time, about one per second."
- WAIS gives 2 trials per length; 2 lives for the whole run is stricter (project-wide rule, not re-proposed); expect scores slightly below norms.
- Visual, not auditory: reading the digits off backward helps some players, so scores may run a bit higher.
- Reference: adults 18–65 averaged ≈ 4.9 digits backward vs 6.5 forward (secondary source). Tentative bands: typical 4–6, very good 7+.

**Symbol Code: R4 / M4 / Score 4 / Overall 4.** A good keyboard version of SDMT / WAIS Coding; the code stays visible
and the next 4 symbols are previewed, like on paper.
- With a key response it is partly a 6-choice reaction task with an arbitrary mapping, like computerized DSST versions. The 20 s chips show how fast the player learns the code.
- The second howTo line is long; splitting it would read better. "Keyboard recommended" is a tip (allowed by the updated rule).
- "Crack the code" hints at a puzzle but is fun; skill line ("processing speed") is accurate; the icon reads well; category Speed is right.
- SDMT: 90 s, correct answers only (max 110). Adult norms unverified (≈ 50–60 written in 90 s, young adults, unverified). Keypresses with 6 symbols should be faster; bands from play data.

Across the five: Odd One Out and Advent round 1 are both click-based visual search but different enough. Passed:
names (no clashes), rules match the code, score units, categories, no diagnostic or IQ claims, color never the only cue
in Change Detection, registry emojis fit.

## Consistency reviewer

Code only. Most of what the five do already follows the shared pattern; one significant finding (Backward Span ties),
the rest small wording, label and helper mismatches.

**Site-wide**
- `docs/SPEC.md:123` says "two-choice tests use ← / →"; when Change Detection is promoted, add ↑ / ↓ as the panel exception. The new `hint` field on AnswerButtons is not in the CLAUDE.md list of shared pieces.
- The same moment handled two ways: Change Detection waits 400 ms after the last answer so its flash shows; Odd One Out and Advent go to the result at once. Pick one for all answer-ending runs.
- Tie-breaker figures with their own sign format: Advent "Switching cost +N ms per door", Odd One Out "Each extra shape +N ms". The site pattern for "how much slower" is `slowdown()` (Stroop, Mental Rotation). Advent's `secs` helper duplicates `fmtMs`.

**Advent Calendar**
- The running clock in the info row has no label (Odd One Out says "Total"): add `label="Time"`.
- A wrong door clears after 350 ms; Odd One Out keeps the wrong shape red until the round ends. Align.
- Score as `toFixed(1)` s vs 2 decimals in Go / No-Go and Line Tracing totals; tenths are enough for 40–90 s (open choice).
- Fine (defines the test): the hand-made door grid with its own colors; the wrong door matches TileGrid's wrong tile; the board ring; RoundResult between rounds; start `quick`; about 1–1.5 min.

**Odd One Out** — no issues beyond the shared points.

**Backward Span**
- Rules: lives are in `howTo`; every lives test puts them in `scoring` ("You have 2 lives: a mistake costs one, and you get …"). Keyboard line: Quick Maths' wording "Type the answer on your keyboard, or click it on the keypad, then press Enter or OK."
- `formatScore` should use `count(s, 'digit')` like Number Memory.
- `BackwardSpanTest.tsx:69-90` copies RoundResult's arming logic: share a `useContinue(onContinue, enabled)` hook. Waiting after a miss differs from every other lives test (they go on after `END_MOMENT_MS`), justified by the three comparison lines; Number Order could adopt it.
- Intro: the info-row middle is empty, other tests show "Get ready" there (minor).

**Change Detection**
- Glossary: "trials" (registry, "Trial n / 40"); the site's word is "round". Use "Round" and "40 rounds".
- Button labels "Same" / "Changed"; every other AnswerButtons choice is uppercase (SAME / MIRRORED, SEEN / NEW, MATCH).
- Registry emoji 🔄 is also Mental Rotation's (shared text): e.g. 🔷.
- Length: ~3.3 s per trial × 40 ≈ 2.2 min, the longest of the prototypes, just over the ~2 min guide: 30–32 trials, a shorter blank, or a "~2–3 min" hint.
- Fine: ↑ / ↓ in the stacked panel buttons, the empty right slot (N-Back does the same), the shape colors (the stimulus), stats only on the result, a saved 0 for a played run.

**Symbol Code**
- Buttons look active during the 3-2-1 (`disabled={remaining <= 0}`), though input is ignored: `disabled={!playing || remaining <= 0}`.
- Fine (intended): start `none` with its own `StartTransition`, S D F · J K L with 1–6 hints, repeat ignored, "Press the key…" wording, `answerStats` plus chips (like Stroop), `failed` on an idle run.

**Score spread (ties)**

| Test | Estimate | Note |
|---|---|---|
| Backward Span | ~30 % on "5 digits", ~27 % on 6 | simulated 20k players, span 5 ± 1.1, 2 lives |
| Number Memory | likely the same | to be replaced by Backward Span |
| Change Detection | ~5 % (estimate) | 0.1 steps over ~1.5–5 |
| Symbol Code | ~3 % (estimate) | whole points over ~30–100 |
| Advent, Odd One Out | negligible | times in ms |

Smallest Backward Span fix: partial credit for the failed length, longest + (correct leading digits of the last miss ÷
length), to 0.1 (e.g. "5.5 digits"); score-changing; the scoring-reviewer should check how much luck it adds.

Passed: one-sentence taglines, "Tests …" skill lines, "click" wording (Symbol Code intentionally recommends the
keyboard); correct − wrong for answer tests; total-time tests add 1 s per wrong click, written the same way; honest 0
on a first-length fail; `higherIsBetter`; exactly one GameInfo each; shared feedback ring; RoundResult; `useLater`;
Space / Enter continue; no key clashes; shared result blocks; lengths 1–2 min (except Change Detection, above); only
the intended one-off colors.

## Play-tester

Played on localhost:5173 (second tab only), desktop, dark. **No bugs in the game logic; no console errors.** The pane
was slow at times (one Odd One Out round took ~10 s of wall time): pane slowness, not a game bug.

Runs saved to localStorage: Advent Calendar 1 (43.4 s, new best over 114.8 s); Odd One Out 2 (69.4 s, 172.3 s);
Backward Span 1 finished (15 digits) + 1 unfinished (not saved); Change Detection 1 (12.0 shapes, new best); Symbol
Code 1 (31 pts) + 1 no-input run ("Not counted", not saved).

Doubtful or polish:
1. Prototypes show "Skip to Aim Trainer ›" on the rules screen and "Next test: Aim Trainer" on the result. SPEC says prototypes are left out of "Next test"; probably intended (it points at a real test), worth confirming.
2. Odd One Out: a click in the first frame after the board appears is ignored (`shownAt` is set in the next rAF). Harmless on a real screen (~16 ms).
3. Backward Span: after a correct answer the "Correct" flash shows but "Score" keeps the old value for 0.9 s until the next length starts (by design, `spanScore(digits)`), which can look like the answer wasn't counted.
4. Symbol Code result chip "1 pts" (no singular).
5. Advent Calendar round-result screen shows only the time and the next instruction; wrong doors / penalty appear only on the final result.
6. Change Detection: 3 mistakes out of 40 gave 12.0, the cap ("Most shapes 12"). A scoring question; it looks generous. *(Main session's note: the play-tester's bot compared the shapes directly, so it was a near-perfect player; the staircase reached the 12-shape cap and the fit returns the cap. Not a scoring bug.)*

What worked: every rules text matches; Advent round 1 and round 2 (★1 → 🌲12 → ★2 → 🌲11 …), wrong door +1 s,
opened doors ignored, round result ignores Enter for 300 ms, final numbers check out (43.4 s = 7.8 + 35.6 with
penalties; switching cost +1157 ms correct); Odd One Out sizes 16 / 24 / 36, "+" pause, "+1 s" note, correct result
stats; Backward Span intro once, keys ignored before input, empty Enter ignored, miss → comparison + continue (Enter
right after the miss ignored), lives, "Out of lives" → result after ~1.5 s, keypad and keys; Change Detection panel,
presses during "Remember them" ignored, mouse and ↑ / ↓, stats match the 40 answers; Symbol Code 3-2-1 on its layout,
presses during it ignored, letters / 1–6 / pad clicks, chips add up (1 + 16 + 14 = 31), no-input run not saved.

Not checked: the "?" overlay and Restart / Back to start; overflow with many chips; Backward Span click-anywhere
continue (keys used); Symbol Code with more than ~3 wrong answers.
